# 03 - RAG 问答（让模型读你的文档）

目标：解决模型"不知道你私有的知识"的问题。做一个能回答**你自己文档**的问答机器人。

## 先理解 RAG 是什么（一句话）
模型训练时没见过你的文档 → 提问时先从你的文档里**检索**相关片段 → 把片段贴进 prompt 一起发给模型 → 模型基于片段回答。

## 分步任务

### 任务 1：准备文档
补全 `TODO 1`。在文件夹里放几段文字（比如课程笔记、公司文档），写一个函数把它们读进来、切成小段（chunk）。先按"每 300 字一切"这个笨办法。

### 任务 2：最简检索（关键词版）
补全 `TODO 2`。不用向量，先用最土的办法：问题里出现了哪个词，就找出包含这个词的文本段。体会"检索"到底在干嘛。

### 任务 3：拼出 RAG 流程
补全 `TODO 3`。把"检索到的片段 + 用户问题"拼成一个 prompt 发给模型。对比：直接问模型 vs 带片段问，回答有什么区别？

### 任务 4：升级检索（向量版，可选）
学有余力再做。调用 embedding 接口把文本段变成向量，存起来；提问时把问题也变成向量，找最相似的片段。这一步需要 embedding 模型，大部分平台都有（比如 `text-embedding-3-small` 或国产对应模型）。

## 完成标准
- [ ] 能回答"我文档里写了什么"这类问题，而不是瞎编
- [ ] 你能画出 RAG 的流程图：文档 → 切分 → 检索 → 拼 prompt → 回答
- [ ] 你知道 RAG 和"微调"的本质区别（一句话能说出来就行）

## 提示
- 切分、检索都不用追求完美，先跑通再优化。
- RAG 最大的坑是"检索不到相关片段"，先检查检索结果，再怀疑模型。
