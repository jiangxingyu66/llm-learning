# 02 - 调用大模型 API

目标：从"在网页上聊天"进化到"用代码指挥模型"。这是做应用的第一步。

## 分步任务

### 任务 1：理解消息结构
补全 `TODO 1`。`messages` 是一个列表，里面有 `system`（设定人设）、`user`（你的问题）、`assistant`（模型之前的回复）。试着改 `system` 为"你是一个严格的语文老师"，看回答风格怎么变。

### 任务 2：多轮对话
补全 `TODO 2`。实现一个能记住上下文的对话：把每一轮的问答都追加进 `messages` 列表。试试先问"我叫小明"，再问"我叫什么"，看模型能不能答对。

### 任务 3：调温度（temperature）
补全 `TODO 3`。用同一个 prompt 分别以 `temperature=0` 和 `temperature=1.2` 各跑 3 次，观察输出的稳定性和创造性有什么区别。想想：写代码、写诗分别该用哪个？

### 任务 4：流式输出
补全 `TODO 4`。加上 `stream=True`，让回答一个字一个字蹦出来（像网页版打字机效果）。这是做聊天应用的必备技能。

### 任务 5：结构化输出（JSON mode）
补全 `TODO 5`。用 `response_format={"type": "json_object"}` 强制模型输出合法 JSON。这是后面做 Agent、做数据处理的基础。

## 完成标准
- [ ] 5 个 TODO 全部补全且能运行
- [ ] 你能解释 system / user / assistant 三个角色的区别
- [ ] 你知道 temperature 什么时候该高、什么时候该低

## 提示
- 报错先看报错信息的前两行，八成是 Key 或模型名写错了。
- 每次调用都会花一点 token，别在循环里无脑调 100 次。
