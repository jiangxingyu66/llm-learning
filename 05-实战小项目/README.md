# 05 - 实战小项目：做一个属于你自己的应用

目标：把 01~04 学的东西串起来，做一个**解决你真实问题**的小应用。这是简历上能写的一行，也是检验学习成果的唯一标准。

## 选题（选一个你真正会用的）

- 📝 **学习笔记问答**：把你的课程笔记扔进去，随时提问（用 03 的 RAG）
- 💬 **群聊总结助手**：粘贴一段聊天记录，输出"讨论了什么、谁说了啥、待办事项"（用 01+02）
- 📧 **邮件/消息改写**：输入大白话，输出得体的正式版本，可选语气（用 01+02）
- 🤖 **小小 Agent**：比如"帮我算账 + 查天气 + 给建议"的多功能助手（用 04）
- 💡 或者你自己的想法，越贴近你的生活越好

## 分步任务

### 第 1 步：写需求（一句话 + 三条验收标准）
比如："做一个群聊总结助手。验收：① 能提取待办事项 ② 输出不超过 200 字 ③ 格式固定为 Markdown。"

### 第 2 步：画流程（纸上画就行）
用户输入 → 哪几步处理 → 输出。标出哪一步用 prompt、哪一步调 API、要不要 RAG。

### 第 3 步：先做最小可用版本
别管界面，别管优化，先让核心流程跑通。能跑 > 好看。

### 第 4 步：迭代 3 次
每次只改一个地方：换个 prompt、加个功能、修个 bug。把每次的改动和效果记下来。

### 第 5 步：写项目 README
在这个文件夹里写一个 `我的项目.md`，包含：项目是干嘛的、怎么运行、用了哪些技术、遇到最难的 bug 是什么、怎么解决的。

## 完成标准
- [ ] 有一个能运行的完整应用（命令行版就行）
- [ ] 写了 `我的项目.md`
- [ ] 你能给别人讲清楚：输入是什么、中间发生了什么、输出是什么

## 提示
- 选**小**题目，3 天能做完的那种。做完一个小的，比开工三个大的有价值得多。
- 过程中任何报错、卡住的地方都可以发给我，这是我最擅长的部分。
